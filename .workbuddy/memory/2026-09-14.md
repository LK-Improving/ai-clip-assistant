## 修复 `pnpm start` 启动报错：Cannot use 'import.meta' outside a module

- **现象**：用户 PowerShell 在仓库根目录跑 `pnpm start` → `Failed to load: apps/desktop/forge.config.ts` → `SyntaxError: Cannot use 'import.meta' outside a module`。
- **定位过程**：
  1. Forge 7.11 用 **jiti** 加载 `.ts` 配置（`@electron-forge/core/dist/util/forge-config.js` 里 `createJiti(...)` + `jiti.import`），不是 ts-node。
  2. 写脚本用 jiti 加载同一份 forge.config.ts 做对照：**Node 22 成功、Node 20 失败**。失败堆栈指向 `vite/dist/node/chunks/config.js` 里的 `import.meta.require("ws")`。
  3. 链路：forge.config.ts → `@electron-forge/plugin-vite` → vite 7（纯 ESM，含 `import.meta.require`）。Node 20 下 jiti 走 CJS 转译，`import.meta` 原样残留 → vm 解析报 SyntaxError；Node 22 下 jiti 走原生加载，正常。
  4. 根因：用户 PowerShell 的 PATH 里 `D:\nodejs`（**Node 20.0.0** + pnpm）在前；而 vite 7 要求 `^20.19 || >=22.12`，本项目实际需要 **Node >= 22.12**。我的 bash PATH 里托管 Node 22.22.2 在前，所以复现不出来。
- **修复**：新增 `apps/desktop/scripts/forge.cjs` 作为 Forge 命令统一入口 —— 当前 Node >= 22.12 则直接跑；否则探测 `MIAOMA_NODE` 环境变量 → WorkBuddy 托管 Node 目录（`C:/Users/LK/.workbuddy/binaries/node/versions/*/node.exe`）→ `C:/Program Files/nodejs`，取满足要求的最高版本重启。package.json 的 `start/package/make/publish` 全部改为 `node scripts/forge.cjs <cmd>`。
- **验证**：
  - Node 20 跑 `node scripts/forge.cjs start` → 打印切换日志，自动改用 22.22.2 → 系统检查通过、vite 构建 preload/main 成功（即配置加载这一关已过）。
  - Node 22 跑 → 无切换日志（直通），同样构建成功。
- 备注：沙箱内 `pnpm start` 能过配置加载并起 Electron，但窗口是否真正常显示仍需用户本地确认。

## 修复「导入视频后预览区黑屏」—— miaoma:// 白名单未持久化

- **现象**：素材库缩略图正常、时间线片段与属性面板数据都对、时长 00:52 也对，但预览区**纯黑无画面**。诡异点是缩略图有画面。
- **定位关键**：缩略图在 `userData/thumbs/` 下能显示 → 说明 miaoma:// 协议本身工作正常；素材本体在 `C:\Users\LK\Downloads\...` → 说明只有素材本体这条路径被拒。
- **根因**：`C:\Users\LK\AppData\Roaming\@miaoma\desktop\library-cache.json` 里 `"directories": []`（空）而 `entries` 有 2 条。用户是用「导入」按钮（pickFiles → `addFiles`）加的素材，`addFiles` 只调了 `addAllowedPath(dirname(file))` **仅在内存生效、不写入 `directories`**；`LibraryStore.load()` 恢复时只遍历 `directories` → 重启后素材目录全部失权 → 协议返回 **403「访问被拒绝」** → `<video>` 加载失败。
- **为什么难发现**：`<video>` 的 `error` 事件不带原因，预览区是静默黑屏，UI 无任何提示。
- **修复**（4 处）：
  1. `main/services/library.ts` `load()`：除 `directories` 外，**从每条 entry 反推 `path.dirname` 补登记白名单**（根因修复，老缓存自动兼容）。
  2. `main/services/library.ts`：新增 `LibraryEntry.imported` 标记；`scan()` 清理时跳过 imported 条目、并保留该标记 —— 否则用户一按「扫描目录」导入的素材就会被清空。
  3. `main/protocol.ts`：新增 `explainAccess()` 诊断（区分「文件不存在」/「路径未授权」）；修 Range 解析 —— 后缀范围 `bytes=-N` 原先被误解析成 `0-N`，越界 `end` 原先直接 416（改为宽容裁剪），多段 Range 直接按整文件返回；`isAllowed` 改为大小写不敏感比较（Windows 盘符大小写）。
  4. `main/ipc.ts` + `preload.ts` + `components/editor/preview.tsx`：新增 `media:diagnose` 通道；预览 video 加 `onError/onLoadedMetadata/onLoadedData`，失败时显示**具体原因 + 素材路径 + 重试按钮**，不再静默黑屏。另 `project:get` 打开工程时也补登记素材目录（原先只在 `project:save` 登记，代码注释里的意图并未生效）。
- **验证方式**（沙箱无 Electron 二进制 `node_modules/electron/dist` 为空，无法起 GUI）：
  - 写临时脚本用 esbuild 把真实 `protocol.ts` / `library.ts` 打包，`electron` 用 stub 替换（`app.getPath` 指向真实 userData、`protocol.handle` 把 handler 挂到 globalThis）。
  - 场景 A 复现：空白名单 → 协议 **403「访问被拒绝」**（黑屏根因确认）。
  - 场景 B/C/D：登记父目录后 200 + `video/mp4` + `Accept-Ranges: bytes`；`bytes=0-1023` → 206；`bytes=-100` → `206 bytes 30296666-30296765/30296766`；越界起点 → 416；缺文件 → 404。
  - 端到端：用**用户真实的坏缓存**跑修复后的 `load()` → 2 条素材全部恢复 200 可访问，**用户重启应用即可，无需重新导入**。
  - `pnpm --filter @miaoma/desktop typecheck` 通过。
- **顺带发现（已核查，先前误判）**：先前以为落盘工程 `assets: []`，实际核查后 `timelineToProject` 早已把素材 `buildAsset` 后 push 进 `project.assets`，`892fbcb0` 工程文件里 assets 是满的；空 assets 是另一个还没加片段的空工程（`71641646`）所致。

- **踩坑**：
  1. **agent tsconfig 的 `rootDir: "src"` 导致 TS6059 刷屏**：根 `tsconfig.base.json` 的 `paths` 故意把 `@miaoma/video-project` 映射到 `packages/core/src/index.ts`（让 typecheck 覆盖 core 源码），而 agent 的 `rootDir` 又把**外部 core 源码排除在 rootDir 之外** → 一堆「File is not under rootDir」。desktop 一直没设 rootDir 所以没报错。**修复：删掉 agent tsconfig 的 `rootDir`**。（`build:core` 产出 dist 并不能绕开——`paths` 的优先级更高。）
  2. `PipelineError` 不能直接重声明 `cause` 字段（TS4114，必须 `override`；且 `Error.cause` 已是 `unknown`）。改用 `super(msg, { cause })` 交给原生 Error。
  3. 根 tsconfig 开了 `noUncheckedIndexedAccess`，`order[i]` / `completed[len-1]` 都要判 undefined。
  4. **同一条消息里连续多个 Edit 可能只有部分生效**：README 的「阶段二」那行改了之后又被读回来的旧覆盖分享内容覆盖，需要**单次编辑 + 立即 Read 复核**。

## 阶段二续：把 AI 引擎接入桌面端（IPC + UI 真实驱动）

- **背景**：引擎跑通后仍是"无 UI 接入"——`pages/ai-workflow.tsx` 与 `pages/storyboard.tsx` 都是阶段三留下的**纯静态 mock**（文案硬编码"1 分钟日本旅行 Vlog"，数据来自 `@/lib/mock`）。本次把这条链路做成真实闭环。
- **交付**：
  1. `main/services/agent.ts`（新）：`createAgentDeps()` 把真实能力装配成 `AgentDeps`（`probe`=desktop probeMedia、`tts`=DesktopTtsAdapter、`llm`=`createLlmProvider()` 由 env 决定）；模块级 `session` 保存中断后的 `resume` 闭包；`startAgentRun` / `resumeAgentRun(scenes?)` / `getAgentStatus` / `cancelAgentRun`；`persist()` 落盘时把素材目录登记进 miaoma:// 白名单（否则编辑器黑屏）。
  2. IPC：`agent:start` / `agent:resume` / `agent:status` / `agent:cancel` + `agent:event` 事件广播；preload 暴露 `agent.*`（含 `onEvent` 订阅）。全局类型是 `electronAPI: DesktopApi = typeof api`，加字段自动生效，无需改 d.ts。
  3. `lib/agent-session.ts`（新）：沿用 `active-project.ts` 的模块级单例 + 订阅 + `bridge()` 降级；`updateScene` / `removeScene`（删除后重排 order，引擎按 order 匹配素材与旁白）。
  4. 两个页面重写为真实驱动：工作台（需求+素材目录+真实节点步骤条+简报+日志）→ 中断自动跳分镜页 → 分镜可编辑 → 确认后续跑 → 落盘并跳编辑器。
  5. 根 `package.json` 新增 `build:agent` / `build:libs`，`dev/build/package/make` 统一走 `build:libs`（**必须先构建 agent 才能构建 desktop**：vite.main 只 external electron 与 node builtins，`@miaoma/agent` 会被打包，其 `main` 指向 `dist/index.cjs`，dist 不存在则解析失败）。
- **关键设计决策：TTS 失败降级而非中断**。本地 TTS 的 `isConfigured()` 只判 `Boolean(config.local.baseUrl)`，而**默认 baseUrl 是 `http://127.0.0.1:7860`（非空）**，所以"配置检查"恒为 true，但服务实际不可达 → `synthesizeSpeech` 必失败。若直接抛出，用户没配 TTS 时整条 AI 剪辑链路直接崩。故 `DesktopTtsAdapter.synthesize` 改为 try/catch，**失败或未配置都降级到 `OfflineTtsProvider`（静音占位）**并记日志告警。这让"没配密钥也想先跑通链路"成为可能。
- **验收**：桌面端冒烟新增 `ringAgentPipeline` 环（真实主进程服务跑「启动 → 分镜中断 → 改旁白/改时长/删一场 → resume → 工程落盘 → 读回 + Zod 校验 + 轨道数=4」），**26 环全绿**；`pnpm typecheck` 三包全绿。
- **踩坑**：
  1. `main/services/agent.ts` 在 `services/` 子目录，导入 protocol 要写 `'../protocol'`（不是 `'./protocol'`）。
  2. `AgentSnapshot` 定义在 `main/services/agent.ts` 而非 `@miaoma/agent`；渲染进程侧用 `import type ... from '@/main/services/agent'`（`import type` 会被 esbuild 擦除，不会把主进程/electron 打进渲染进程）。
  3. 测试环最初只喂了图片+音频目录 → 离线分镜只出 1 场，"删除分镜"分支没被覆盖；补上视频目录后出 2 场才真正走到删除+重排。
