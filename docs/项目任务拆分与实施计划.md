项目任务拆分与实施计划

第一阶段：基础设施与工程化搭建
目标：完成项目脚手架搭建，确立 Monorepo 架构，确保开发环境跑通。

模块 1.1：Monorepo 仓库初始化
任务：
初始化 pnpm workspace。
创建目录结构：apps/desktop (应用层), packages/agent (智能体层), packages/core (数据模型层)。
配置 tsconfig 基础配置和路径别名。
产出：一个可以使用 pnpm install 正常安装依赖的空仓库。

模块 1.2：数据模型 DSL 开发 (@miaoma/video-project)
任务：
基于 Zod 定义视频项目的数据结构（Project, Track, Clip, Asset）。
设计判别联合类型（Discriminated Unions）来区分视频片段、音频片段、字幕片段。
实现版本控制字段 schemaVersion，为未来升级留后路。
产出：一个独立的 npm 包，提供类型安全的视频项目定义。

模块 1.3：Electron 桌面端骨架 (apps/desktop)
任务：
集成 Electron Forge + Vite + React 19。
配置主进程（Main）、预加载脚本（Preload）、渲染进程（Renderer）的三层通信桥梁。
接入 TailwindCSS 4.0 和 Shadcn/ui 组件库。
产出：一个能启动的空白桌面窗口，控制台无报错。

第二阶段：AI 智能体核心引擎开发
目标：实现“大脑”，即不依赖界面的后台逻辑，确保 AI 能按流程工作。

模块 2.1：Provider 适配器层
任务：
封装 LLM Provider（对接字节火山方舟/兼容 OpenAI 协议）。
封装 TTS Provider（抽象接口，预留火山引擎和本地 Index-TTS 2 的切换能力）。
封装 FFmpeg Provider（封装 fluent-ffmpeg 或 child_process 调用）。
产出：统一的接口调用层，上层业务无需关心具体是哪个厂商的 API。

模块 2.2：LangGraph 工作流编排
任务：
定义 State（状态机数据）。
实现核心节点：素材扫描 -> 创意简报 -> 分镜规划 -> 素材匹配 -> 语音合成 -> 时间线组装。
实现 Checkpoint 机制，支持断点续传。
产出：一个可以在 Node.js 环境下运行的脚本，输入需求，输出 JSON 格式的分镜脚本。

模块 2.3：人机交互中断机制
任务：
在“分镜规划”节点后设置中断点。
实现 resume 方法，允许外部修改状态后继续执行后续节点。
产出：智能体支持“暂停-人工修改-继续”的交互模式。

第三阶段：核心业务功能与编辑器
目标：实现用户看得见、摸得着的功能，完成从素材到成片的关键链路。

模块 3.1：本地素材管理系统
任务：
基于 ffprobe 实现音视频元数据提取（时长、分辨率、码率）。
实现文件扫描器，支持增量扫描（对比修改时间）。
生成关键帧缩略图（使用 FFmpeg 截图）。
产出：左侧素材库面板，能显示本地视频列表和元数据。

模块 3.2：可视化编辑器 UI
任务：
实现经典五区布局（工具栏、素材/分镜、预览、属性、时间线）。
开发时间线组件（支持拖拽、缩放、轨道管理）。
实现预览区与时间线的联动（点击跳转、播放同步）。
产出：一个静态的、可交互的剪辑界面。

模块 3.3：TTS 语音合成与缓存
任务：
接入火山引擎 WebSocket 流式 TTS。
实现本地 LRU 缓存策略（相同文本不重复请求）。
实现本地 Index-TTS 2 的调用接口（用于隐私模式）。
产出：输入文字能生成音频文件，并自动加载到项目中。

第四阶段：FFmpeg 渲染与桌面集成
目标：打通“最后一公里”，将数据转化为真实的视频文件，并完善桌面应用特性。

模块 4.1：FFmpeg 复杂滤镜构建器
任务：
编写算法将时间线 JSON 转换为 FFmpeg filter_complex 字符串。
处理多轨道视频叠加、音频混音、字幕烧录（drawtext）。
处理跨平台路径转义和字体兼容性问题。
产出：一个 Node.js 函数，输入项目 JSON，输出 MP4 文件。

模块 4.2：IPC 通信与进程管理
任务：
实现渲染进程与主进程的 invoke/handle 通信。
实现渲染进程与智能体引擎的 SSE (Server-Sent Events) 通信，用于实时显示 AI 生成进度（打字机效果）。
实现 AbortController，支持用户取消正在进行的 AI 任务或渲染任务。
产出：前端能实时看到 AI 的思考过程，且能随时叫停。

模块 4.3：安全与本地文件协议
任务：
注册自定义协议（如 miaoma://）加载本地资源，解决 file:// 跨域和权限问题。
实现 Range 请求支持，让 <video> 标签支持进度条拖动。
产出：预览区流畅播放本地大视频，无跨域报错。

第五阶段：打包、测试与发布
目标：交付给用户使用的安装包。

模块 5.1：跨平台打包配置
任务：
配置 Electron Forge Maker（Windows nsis, macOS dmg/pkg）。
处理 FFmpeg 二进制文件的打包与路径引用（开发环境 vs 生产环境）。
代码签名（Code Signing）配置（如有证书）。
产出：可安装的 .exe 或 .dmg 文件。

模块 5.2：全链路测试与优化
任务：
端到端测试：从导入素材到导出视频的全流程跑通。
异常处理：断网、素材损坏、磁盘空间不足等场景的兜底。
性能优化：大项目加载速度、渲染速度优化。
产出：稳定的 Release 版本。

MVP 开发顺序建议
为了让你尽快看到效果，建议按照以下顺序穿插进行：
先做 1.1, 1.2, 1.3：把架子搭好。
接着做 2.1, 2.2：先让 AI 在控制台里跑通流程，生成 JSON。
然后做 3.1, 4.1：确保 FFmpeg 能根据手动写的 JSON 生成视频（验证核心渲染能力）。
再做 3.2, 4.2：把界面做出来，把 AI 和 渲染串起来。
最后做 TTS 和 细节优化。
